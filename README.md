# Dashboard

服务器现成 shell / PowerShell 脚本搬浏览器跑：参数可填、输出实时可见、每次运行留档。同界面还有 IPv6 DNS 控制台：保持一条 AAAA 记录指向本机公网 IPv6。

English: [README.en.md](README.en.md)

---

## 目的

把散在各台机器上的脚本收拢成一份可点击、可留档、主机侧零依赖的运行时 —— 它不是编排器、配置管理或 CI，只负责跑已有脚本并留下记录。

## 快速开始

```bash
cp .env.example .env      # 按需设置登录凭据
docker compose up -d --build
```

开 `http://<宿主地址>:50014`（或 `.env` 中 `DASHBOARD_PORT`）。界面依次：加 Target（SSH 目标）→ 加 Source（脚本来源）→ 同步 → 运行。

## docker compose

用 **host 网络**（不是端口映射），宿主须有**公网 IPv6 地址** —— 本地检测需要读取宿主机网卡，ipify 检测还需要公网 IPv6 出站能力；网桥网络看到的是容器自己的网卡。其余说明见 `compose.yaml` 的文件头注释。

## 环境变量

写 `.env`。数据默认保存在宿主机 `./data`，脚本源保存在 `./data/scripts`，统一挂载到容器 `/data`。目标主机执行目录仍在界面单独设置。

| 变量 | 含义 |
|---|---|
| `DATA_DIR_HOST` | 数据、密钥和脚本的宿主机根目录，默认 `./data` |
| `AUTH_USERNAME` / `AUTH_PASSWORD` | 登录凭据，**要么都设要么都不设**；不设即开放访问（启动告警） |

端口、目录属主、并发上限、超时、日志与保留策略、`SECRET_KEY`、`GIT_PROXY`、构建镜像源等，见 `.env.example` 的逐项说明。

## 旧版脚本目录迁移

升级前停止服务并备份数据，将原 `SCRIPT_ROOT_HOST`（默认 `./workspace`）目录的**内容**完整复制到 `DATA_DIR_HOST/scripts`（默认 `./data/scripts`），包含隐藏文件并保留原子目录结构。目标目录有同名文件时先核对，避免覆盖；确认运行用户有读写权限。来源保存的是相对路径，无需修改数据库。

移除旧 `.env` 中的 `SCRIPT_ROOT_HOST`，以及自定义 Compose 中的 `/workspace` 挂载；如曾显式设置 `SCRIPT_ROOT_CONTAINER`，移除该覆盖以使用新默认值。重新构建并启动后，核对本地来源文件和 GitHub 来源同步，再测试运行。确认前保留原目录和备份；回退时恢复旧配置与旧目录。

## 写脚本

来源里任何 `.sh` / `.ps1` 都收录（分别用 `bash` 与 `pwsh` 跑，后者需目标机已装）。脚本**开头**注释块变成界面表单：

```bash
# @name Deploy API
# @timeout 600
# @param ENV required Target environment
# @param REPLICAS type=number default=3 How many replicas
```

声明参数以**环境变量**传入。脚本未声明的值可临时加：运行表单每行选 `env`（环境变量，名须是 shell 标识符）或 `argv`（位置参数 `$1 $2`，按行序，名只是标签）。每个脚本表单记住上次填的内容。

## 模型能力（MCP）

「模型能力」为 Agent 提供 Ollama 图像理解工具。添加 Ollama 端点、刷新模型列表后，在能力设置中配置模型和优先级回退路由。可测试端点、用内置样例真实测试能力、查看每次路由尝试，并复制 MCP 客户端配置。支持 JPEG、PNG、WebP Base64 图片，客户端不能指定上游模型或 URL。

设置页可查看/轮转 MCP API Key，调整单张图片大小、调用并发和 MCP 网络访问范围。管理页面共用 dashboard 登录，MCP 使用独立 Bearer Key；请配置 dashboard 登录凭据。MCP 地址为 `http://<宿主地址>:<DASHBOARD_PORT>/mcp`，不再使用原独立服务的端口。服务不会在日志中打印密钥。

配置保存在 `DATA_DIR/model-ext-mcp.sqlite`。迁移旧部署时先停止旧服务并备份数据，将原数据库的一致快照移入同一目录，保留 dashboard 自身数据库与密钥。原 `/api/v1` 管理 API 改为 `/api/model-relay` 并使用 dashboard 会话。Node.js 本地运行需 24 或以上。

关闭 MCP 网络访问时，只放行 TCP 对端属于本机或本机网段的请求，不信任转发头。默认 host 网络下，这包含宿主机局域网；同机反向代理视为本机，请按实际需求限制代理或防火墙。

## 脚本定时运行

「定时运行」独立页面中创建具名计划，配置脚本、五段 Cron、时区、目标主机和运行参数；同一脚本可以设置多条计划。每条计划都有独立执行记录，可打开详情查看日志，并可设置记录保留天数（0 表示永久保留）。计划持久保存，执行日志进入运行历史；服务停机期间不补跑，上次定时执行未结束时跳过本次触发。

## IPv6 DNS 控制台

「DNS」页把一条 AAAA 记录保持指向本机的公网 IPv6，服务商支持 Cloudflare。

- 顶部「设置」打开弹窗，配置服务商、凭据、IPv6 检测来源与检查间隔；凭据区可折叠。
- 顶部操作按钮用于探测公网 IPv6、查询记录、手动检查并更新；操作结果持续显示到下次操作或离开页面。
- 状态卡片展示地址、解析记录及定时任务的下次执行时间、上次执行时间与结果。历史预览下点击「查看全部」，打开检查统计和分页明细。
- 状态卡片随屏幕宽度调整列数；界面支持中文和英文。

IPv6 检测来源可选 ipify（默认）或本地网卡；保存后，地址检测、手动更新和定时更新统一使用该来源。ipify 需要公网 IPv6 出站能力；若使用 Clash/Mihomo 等 Fake-IP DNS，请让 `api6.ipify.org` 返回真实地址并直连。本地检测读取 Linux 网卡上的稳定公网 IPv6，排除私有、临时、失效和尚未就绪的地址；可指定网卡名称（如 `enp1s0`），留空时自动检测。没有可用地址或存在多个候选时停止更新，不会自动切换来源。容器需使用 host 网络才能读取宿主机网卡地址；本地检测不需要访问 ipify，但更新 DNS 仍需要连接服务商 API。定时任务的上次执行状态在服务重启后清空，检查历史保留。

Gotify 统一在设置页配置；测试消息可使用尚未保存的表单值，且不受自动通知开关影响。

## 设置页

`/#/settings` 放整个仪表盘的偏好：界面语言（English / 简体中文），以及 Gotify 通知的地址、令牌和「脚本运行结果通知」「DNS 更新通知」开关。

保存 Gotify 地址与令牌并开启「脚本运行结果通知」后，手动和定时执行的脚本在成功、失败、超时或运行中取消时会自动发送结果通知，包含脚本名、目标名、结果、耗时和运行 ID，不包含参数、日志或错误原文。未配置时不发送；发送失败只记录服务日志，不改变执行结果。排队时取消、重启中断不通知；通知不重试或补发。消息使用中英双语。「DNS 更新通知」独立控制 AAAA 记录创建或地址变化后的通知。
