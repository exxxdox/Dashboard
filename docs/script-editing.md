# 本地脚本管理

脚本库按来源区分写入权限：本地来源可以在网页新建、查看、编辑、删除 `.sh` 和 `.ps1` 文件；GitHub 来源的文件保持只读，通过仓库修改后同步更新。脚本名称、运行设置等原有配置入口继续可用。

## 操作

本地来源显示“重新扫描”，GitHub 来源显示“同步”。网页中的修改即时生效；直接在目录中增删或修改文件后，请重新扫描，以更新脚本列表和信息。扫描状态和时间只记录扫描操作，不代表网页改动尚未保存。

- 选择本地来源，点击“新建脚本”，输入相对文件路径和源码。路径可以包含子目录；同名文件不会被覆盖。
- 选择脚本，在源码区点击“编辑脚本”。编辑器读取完整 UTF-8 内容，保存后更新目录树、参数声明和脚本信息，无需手动同步。
- 在脚本配置中修改“文件名”会直接重命名本地文件，不移动目录、不切换脚本格式；省略扩展名时保留原扩展名。同名文件及已有历史记录占用的路径不可覆盖。脚本 ID、执行历史、运行草稿和定时计划保持关联。GitHub 来源仍只修改显示名称。
- 点击“删除脚本”并确认后删除实际文件。执行历史保留，关联定时计划停用；重新创建同路径文件不会自动恢复计划。
- 关闭有改动的编辑器或通过浏览器后退离开时需要确认放弃。保存失败时保留输入；文件在编辑期间发生变化会拒绝保存或删除，需要重新打开后核对最新内容。

## 文件与数据边界

各来源目录必须彼此独立，不能相同或互为父子目录，避免 Git 同步或删除来源时影响其他来源。旧配置若有目录重叠，会拒绝同步和连文件删除；可先保留文件删除来源记录，再用独立目录重新配置。

文件读写仅允许位于本地来源目录内，拒绝路径穿越、符号链接、硬链接文件、隐藏路径和扫描器排除的目录；也不能通过本地来源访问另一个 GitHub 来源的目录。每个文件限制为 2 MiB，只接受可无损读取的 UTF-8 内容。目录必须具有相应读写权限。

保存使用同目录临时文件原子替换，保留原文件权限；新建不覆盖已有文件。脚本元数据复用扫描规则，仅更新当前文件，不将其他文件误判为删除。数据库记录沿用软删除，以保留历史关联。来源同步期间拒绝文件操作、来源配置修改及删除，并拒绝同来源重叠同步，避免同步结果覆盖编辑结果。

内容哈希用于检测从读取到提交之间的版本变化。运行中的任务使用提交运行时取得的脚本快照，修改和删除影响之后的运行。文件与数据库仍应一起备份；进程或主机突然停止不等同于跨文件系统与数据库的事务回滚。
